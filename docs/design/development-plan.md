# 分步开发计划

> 范围已更新：一期纯本地、云同步二期。当前执行以[本地一期计划](../local-first/README.md)为准；本页云同步内容保留作二期设计参考，S01工程基础可复用。

版本：1。日期：2026-10-20。状态：S01已开始开发，其余检查点尚未进入验收。

本计划把原L0–L3拆成14个可单独交付、验证和追踪的开发检查点。S00是已完成的设计准备，不是一个可运行应用。执行顺序、测试归属与状态登记在[阶段合同](contracts/stage-plan.json)，验收操作在[分步验收手册](stage-acceptance.md)。

## 执行规则

1. 一次只宣布一个当前检查点。先做本点的可运行增量，再跑本点检查并交付证据，不以“模块代码基本写完”代表通过。
2. 每点都提供明确数据根、启动/验证命令、产物位置与已知限制。测试只使用隔离用户、临时媒体和夹具，不触碰生产照片。
3. 技术验收存在失败或关键NOT RUN时，本点不通过；依赖它的下一点不得以“后面补测”越过。可继续处理失败、完善测试或独立文档，不推进依赖的功能。
4. 技术验收和用户体验确认分别记录。交付可体验成果不等于用户已确认；没有反馈也不自动记为用户通过。未收到要求等待确认的指令时，按技术门槛继续，不增设每步都要授权的流程。
5. 每点只执行直接相关检查和受影响回归；S14对最终代码树执行完整交付门槛。影响已有结论的代码/资源/配置变化需重验，单纯文档改动不要求重复性能跑分。
6. Android/Windows始终planned，直到后续平台专属验收。Linux上的窄窗口和假URI适配器只能证明布局/接口，不算移动端已支持。
7. 性能与玻璃在S03/S04开始开发并提前设门槛，S13做真实功能整合后的全面复验，不能等全部同步写完才发现框架或渲染不可行。

## S00 设计准备

已存在：模块、SQL、profile、视觉token、验收矩阵和设计检查器。此次补齐开发顺序、阶段门槛与证据模板。技术状态为design-only通过；用户体验确认不适用，应用测试仍未执行。

## S01 Linux工程与平台配置

**前置：S00。模块：M01/M02/M03/M12/M15。**

开发顺序：

1. 建立Flutter工程与Rust workspace，落实photo-domain/core/gateway/bridge/platform-linux依赖方向；禁止直接引用旧应用crate。
2. 安装并实测工具链，锁定Flutter/FRB/Rust和依赖版本；记录本地构建前提。
3. 实现Linux profile解析/验证/摘要生成，Dart/Rust初始化核对摘要与bridge版本。
4. 打通异步调用、事件和关闭入口，提供可启动Linux窗口。
5. 建立开发启动及阶段验证入口；后续未实现阶段返回未实现，不能生成假PASS。

交付：可启动开发bundle、版本/构建描述、一个往返调用与事件样本、配置错误演示。此点不宣称数据库或同步已可用。

验收：按手册S01验证真实构建/启动、摘要不一致、planned目标和错误适配器拒绝；不能只提交绑定生成代码。

## S02 数据库与运行时

**前置：S01。模块：M01/M05/M12，Linux存储和进程锁。**

开发顺序：

1. 把设计schema落实为初始迁移，创建单writer、短读连接和作用域校验。
2. 实现Engine状态、根锁、ProcessId/epoch、正常退出和Interrupted记录。
3. 实现提交后事件与订阅快照屏障、队列溢出ResyncRequired。
4. 加入迁移/IO错误处理；严禁自动清空用户库。
5. 提供可重建的隔离夹具入口，供S03/S04使用；夹具构造不替代后续协议旅程。

交付：窗口可显示真实核心状态与隔离库摘要；重复启动、回滚和迁移失败的复现记录。

验收：实际Engine/actor/bridge路径，不只跑设计SQL。发布文件恢复和完整账号切换在相应后续点完成，报告明确边界。

## S03 本地图库与玻璃组件

**前置：S02。模块：M09/M11/M12/M13/M17的最小可浏览切片。**

开发顺序：

1. 准备1,000张独立身份/资源引用的合法图片夹具，经正式ReadStore/FFI查询显示。
2. 完成虚拟网格、查看器、分页、锚点和媒体lease；不在Dart硬编码图库列表。
3. 建立三宽度共享导航、明暗主题与full/reduced/plain玻璃组件。
4. 实现按下/选中/焦点/hover、基础键盘与触摸语义；暂未接入的同步操作不做成功假反馈。
5. 记录缓存/句柄/重绘范围，为S04接入窄索引。

交付：可离线体验的图库原型、390/800/1440宽度与两主题截图、真实输入录制/日志。视觉样本只代表原型，不签收整个M13/M17。

## S04 十万图库前置性能门槛

**前置：S03。模块：M05/M09/M11/M12/M13/M16/M17。**

开发顺序：

1. 实现事务维护读投影、根组/稀疏收藏/深路径索引。
2. 实现Rust窄键BrowseIndex、rank窗口、跳转、增量更新和过时请求取消。
3. 实现DTO/图片/解码预算和可见优先预取，输出FrameTiming、RSS和句柄计数。
4. 升到10,000/50,000/100,000项，验证末段跳转无大OFFSET。
5. 在full和plain材质中分别完成前置性能测试；不具备门槛时先调整架构再接同步。

交付：10万有效本地资源夹具、可运行浏览原型、构建/环境/缓存条件、原始trace/CSV和瓶颈报告。夹具不依赖远端下载，但普通查询/媒体读取/渲染必须走正式路径。

放行必须满足手册S04的首屏、窗口/跳转、60秒滚动、RSS和有界对象门槛。同步并行、DPR=2完整矩阵和10分钟泄漏检查留S13，不提前标为已通过。

## S05 账号与平台凭证

**前置：S04。模块：M03/M04/M06/M12/M13。**

开发顺序：

1. 实现Linux Secret Service与凭证意图补偿，探测锁定/不可用状态。
2. 实现登录草稿、同源请求、普通账号能力/zone选择、接受/取消。
3. 固定endpoint/user/scope，绑定会话引用；密码/token不进入DB或通用DTO。
4. 实现重新登录/退出和身份不符拒绝。此时先验证空库账户；繁忙同步切换在S12验收。

交付：连接临时真实SyncServer的登录流程，以及普通用户/管理员/错误密码/凭证锁定/补偿旅程。

## S06 元数据可靠接收

**前置：S05。模块：M05/M06/M07。**

开发顺序：共享快照与两类型流→页事务/marker→配对投影→固定水位增量/墓碑→unsupported阻塞与token恢复证据。

交付：真实服务产生的元数据、接收计数和待办，可重启续页；资源阶段未完成的照片不放进普通图库。

验收包含分页间并发写入、页重放、HTTP200逐项错误、半页事务回滚。上行门槛不能用ingest冒充applied。

## S07 完整下行与浏览

**前置：S06。模块：M07/M09/M11/M12/M13。**

开发顺序：流式双资源→长度/SHA核验→规范缩略图/缓存→不可变目录提升→SQL可见指针→图库事件与本地查看。

交付：从真实服务逐张下行的可用照片、收藏/路径投影和查看器；断网后浏览已完整副本。

验收先阻断一个角色，再释放，证明只有完整照片出现；内容更新期间继续显示旧完整版本。格式/隐藏/回收站边界准确，不向普通图库泄露。

## S08 下行与发布故障恢复

**前置：S07。模块：M01/M03/M05/M07/M09。**

开发顺序：实现恢复扫描所有权→逐发布崩溃点注入→缓存/文件丢失修复→GC引用保护→token过期和generation变化边界。

交付：故障注入开关（测试构建）、恢复脚本、每个切点的前后状态证据。已验证完整资源复用；文件占用/空间不足保持旧版本。

验收必须真的终止/重启进程或触发指定失败，不能把DB手改成完成态。

## S09 显式导入

**前置：S08。模块：M03/M09/M10/M11/M13。**

开发顺序：文件/目录选择→预览与明确范围→稳定Reader快照→复制/摘要→方向与规范缩略图→本地发布→批准范围义务。

交付：可通过真实UI导入照片并离线浏览；能区分仅导入、允许上传和上传尚未接入。源文件保持原样。

验收覆盖取消、来源中途变化、路径冲突、重复导入、不支持格式、非路径假适配器和中断恢复。

## S10 成对上传与租约

**前置：S09。模块：M05/M06/M08/M09。**

开发顺序：持久版本推导→正常下行→获取/保活/门槛→PreparingAssets→冻结规范请求→阶段写入→完整结果/回执→版本确认。

交付：新客户端把导入照片真实上传，第二个隔离客户端从服务端得到相同原始字节与规范缩略图；日志可追踪operation/run/批次。

验收含双设备争锁、失锁、配额、单图失败、缺缩略图deferred和提交后丢响应。协议delete/modify阶段可在隔离服务测试，不因此开放删除/编辑UI。

## S11 收藏、并发与互操作

**前置：S10。模块：M04/M05/M07/M08/M11/M12。**

开发顺序：确定目标值的收藏命令→metadata类别版本→条件更新/冲突事件→旧回调保护→新旧客户端双向旅程。

交付：收藏能跨端反映且不新增资源；新客户端/旧PhotoViewer在隔离账号/目录中互读并更新同一照片。支持范围外的动作明确不可用。

验收覆盖上行期间再次收藏、同身份竞争、不同身份同路径、响应未知重启、逐项失败与配置捕获；不能把仅Synthetic网关测试当旧客户端互操作。

## S12 设置、生命周期与调度

**前置：S11。模块：M01/M04/M05/M11/M12/M13/M14。**

开发顺序：配置草稿→pending意图/安全停止/生效→暂停/继续/总开关→繁忙账号切换/退出→本地10秒去抖/恢复/有界续批→聚合状态与诊断。

交付：完整设置可用，运行控制与详情展开分离；有效配置自动继续，取消/无效/no-op无副作用；切账号无旧图闪现或旧写入。

验收覆盖快速多次保存、关闭重启、迟到响应、事件溢出、无空闲轮询和失败不自旋。三宽度主流程此时完成一次完整功能验收。

## S13 综合性能与液态玻璃

**前置：S12。模块：全部，重点M13/M14/M16/M17。**

开发顺序：冻结候选功能→复验大图库索引/缓存→加入真实下行/上行并行→完成冷/热、DPR和材质矩阵→长时内存/句柄→视觉与无障碍→修复并按影响重验。

交付：同候选构建的10万图库性能报告、原始样本、full/auto降级轨迹、真实合成桌面视觉/输入证据、全部异常旅程汇总。

所有M16/M17强制项达到门槛才通过；不能通过减少样本量或一直关闭玻璃换取“通过”。

## S14 最终打包与发布候选验收

**前置：S13。模块：M15及最终受影响模块。**

开发顺序：冻结代码/依赖/资源→完整检查→Linux release bundle/启动入口/依赖清单→独立安装目录运行→重启/升级/主旅程→最终验收报告。

交付：本地Linux安装产物、SHA-256、build/profile/source digest、支持环境/已知限制、逐阶段及最终验收记录。没有授权的push、GitHub发布和部署不作为隐含步骤。

必须核对性能结果绑定的二进制/原生库/资源与最终产物一致；不一致按影响重跑S13相关场景。打包后再验证真实玻璃、基本滚动与主旅程。最终完整检查未跑或失败，不算Linux首版交付。

## 回归与返工

| 变更 | 至少重新打开的检查点 |
|---|---|
| schema/迁移/账号作用域 | S02；涉及恢复再S08，版本确认再S11，读投影再S04/S13 |
| codec/资源布局/lease/GC | S07/S08/S09及S13内存/滚动受影响项 |
| 认证/协议/租约/幂等 | S05–S08、S10/S11中受影响旅程 |
| FFI/运行时/事件 | S01/S02/S12及S13泄漏/并发相关项 |
| 布局/材质/shader/图片缓存 | S03/S04/S13；最终包变化还要S14 |
| 只改文字文档且产物未变 | 文档检查，不重跑无关应用性能 |

依赖门槛需重验时，后续点不能继续冒用当前构建的passed状态；保留历史报告。未受影响的检查可以经范围/构建适用性核对复用证据，不因此强制重跑全部功能。

已完成点可以因后续变更重新变为needs_retest，旧报告保留但不能冒用为新构建通过。关键数据损坏、错账号或丢dirty缺陷不作为“已知限制”放行。
