# 缩略图调度与性能迁移

日期：2026-10-22。当前 Flutter 客户端迁入旧 GTK 客户端的缩略图优化；原图始终只读，不改变图库身份或数据库版本。

## 解码与缓存

Linux JPEG 优先使用与旧版相同的 libjpeg-turbo IDCT 缩放解码。C shim 使用已校验文件句柄的副本，并将输入限制在捕获的原始文件范围；错误由 C 的 setjmp 边界处理。Rust 在解码前后与发布前检查文件身份、大小和纳秒 mtime。中间图像与副本继续受解码预算准入控制，不支持的 JPEG 回退到现有 Rust 解码路径。PNG 的行式缩放和其他格式的预算回退继续保留。

输出仍为质量 90 的 JPEG，编码缓存版本为 r4。尺寸为 256、512、1024 三档；请求较小尺寸时，可以复用同一内容版本中已经存在的较大缓存。发布采用同目录临时文件与原子 rename。原有预览、动态照片提取文件不因编码版本升级被删除。

## 调度与内存

每个图库会话拥有一个有界工作队列，容量为 8192 个独立缓存键。键由媒体 ID、内容版本和尺寸组成。可见请求优先于背景封面；全局合并同键工作，多个调用者共享一次生成。最后一个观察者离开后取消尚未开始的工作；已经开始的工作完成后仍能发布缓存。

磁盘命中直接返回，不进入生成队列，不做生成状态写入，也不为命中项查询云端缩略图。缓存路径有独立的 512 项前台 LRU；后台预热不加入该 LRU。Flutter 请求池跨网格、胶片条、相册封面、侧栏和背景共享在途请求与已完成路径；ID-only 封面由原生调度器解析当前内容版本并支持取消。独立保留已解码的 ImageStreamCompleter：前台最多 512 项/96 MiB，后台 64 项/16 MiB，EXIF 768 项/12 MiB；任一项数或字节预算超限均回收。后台晋升前台复用同一 completer，避免重复读盘和 JPEG 解码，解码尚未完成时晋升也正确记账。原图沿用独立的全局 128 MiB 图片缓存。Widget 复用时检查 gateway 身份、内容版本和缓存 epoch；释放或清空后的迟到结果不再创建完成通知计时器。

等待完整缩略图时，最多四个并发任务从 JPEG 前 256 KiB 提取 IFD1 内嵌缩略图。EXIF 小图应用主图方向、检查输出边界，并在 Flutter 侧以独立的 768 项索引复用；它不会把完整缩略图任务标为完成，也不会覆盖已经显示的完整图片。

## 预热、状态与容量

扫描时暂停预热，扫描结束后恢复。后台按设置的线程数把缺失缩略图分批放入共享优先队列，与前台共用工作线程；前台请求优先，后台在有空位时持续补充任务。修改线程数立即作用于当前会话；降低数量时已开始的工作先完成，多余线程随后休眠。窗口通过节流后的媒体 ID 和尺寸调整预热位置，锚点按完整图库排序解释，不按“尚未生成的结果集”计算偏移。清理缓存会主动启用后台重建，无需滚动或发起可见图片请求；扫描期间的暂停仍保留，由扫描结束后恢复。

预热先按 100 行分批核对实际缓存，再按工作线程容量分批拉取缺失工作。状态写入现有关系表 `thumbnails`，限定图库、媒体 ID、内容版本、尺寸与编码版本。成功或失败均在交付前记账，失败项不会被后台无限重试。重试按钮会先失效坏缓存及其失败标记，再重新请求。

扫描结束后的本地变更通知使用 `watch::Sender::send_modify` 原地递增代次。不能在 `send_replace(sender.borrow()...)` 的同一条语句里保留读锁并申请写锁，否则通知自锁，扫描守卫无法退出，缩略图预热一直暂停，进度也停留在隐藏提示的核对阶段。

2026-10-22 真实环境验证：通过 `tools/run_app release --build` 重建并启动默认图库，保留真实桌面、文件和 10 线程配置。修复前缩略图数量停滞；修复后不滚动即可补齐至 392/392，辅助功能树读到“正在索引中 344/392”，完成后提示消失。本次实测覆盖启动后缺失缓存的后台补齐，没有执行完整 UX 验收矩阵；缓存清理、并发调整和通知死锁另有定向回归测试。

网格底部固定浮层显示“缩略图 已就绪/总数”，全部就绪后隐藏；设置中保留状态。失败数单独显示，避免把失败当作完成。独立 Consumer 每秒读取状态，不随进度重建整张网格，也不改变滚动几何。完成或达到容量限制后停止轮询；缓存完成、图库变化、切换尺寸和重试会重新唤醒。原生预热收敛后同样休眠，等待库变更。

Month/Day 预热 512 档，Year 预热 256 档。方形 cover 根据源图短边、裁剪倍率和设备像素选择尺寸，避免长图裁剪后模糊。实际解码目标按 64 像素分桶，窗口逐像素变化不重复解码。每帧最多提交 24 个独立缩略图请求，已回收的排队 cell 不再提交。下一约两屏、最多 64 个已驻留 DTO 只查询现成缓存路径，绝不因此生成原图缩略图；后台每次只解码一张并让出 16 ms，视口变化以 200 ms 合并。

缓存维护在空闲 worker 执行，保留仍属于图库的回收站、缺失与云端媒体缓存，不跟随符号链接。磁盘缩略图按文件时间控制在 2 GiB 内，删除孤儿媒体缓存。达到容量上限后停止本轮全库预热，继续允许前台按需请求，防止删除后立即全库再生成的循环。清理及容量回收会推进缓存 epoch，使 Flutter 请求池失效旧路径。

生成速度支持 1、2、4 个 worker，以及受进程可用 CPU 数约束的物理核心数档位；最大 32。设置下次启动生效。默认仍为 2。

## 观测与定向验证

`thumbnailStats` 返回就绪、失败、排队、运行、生成耗时、最长排队耗时、命中、合并与取消计数。默认日志每 32 项记录一次批次摘要，预热收敛时记录完整/部分完成；慢任务额外记录耗时，不输出原图路径。

验证范围包含：核心调度、取消与合并、缓存快速路径、预热恢复、坏缓存、自适应容量停止；Flutter 请求池、真实 tile 复用释放、背景与胶片条调用方、进度完成隐藏；JPEG 方向、源文件变化、符号链接、原子发布、内嵌 EXIF 小图。只执行相关用例，不运行全量测试。

Linux 构建新增系统 libjpeg 开发头文件与链接依赖（Fedora 为 `libjpeg-turbo-devel`）。正常构建和运行继续使用 `tools/run_app` 与 `tools/platform`。

## 浏览器渐进显示

普通照片在原图实际产生解码帧之前保留缩略图，失败时保留仍可显示的预览。HEIC 转换、动图帧准备和动态照片视频提取期间也保留静态画面。视频以暂停方式打开，等待 `waitUntilFirstFrameRendered`，Linux 还会排除插件初始化的 1×1 空纹理，确认实际输出尺寸后，揭开静态层并经过一帧后再播放；旧路径迟到的回调由 generation 拒绝。动图首次解码完成才启动定时器，后续帧 gapless 播放，TickerMode 关闭时暂停计时。

浏览器预取 ±1 邻居的 DTO、缩略图及其有界解码结果，并只对原图给出最多 16 MiB 的 OS 页缓存提示；不为邻居完整解码原图。切换最多等待目标预览 400 ms，期间保留当前画面；连续按键以最新导航 token 为准。元数据请求按 gateway、媒体、内容版本合并和缓存。大图按视口、设备像素和缩放限制双轴解码，最大边 4096。

## 扫描、查询与同步

扫描复用一次有界文件头读取完成常见图像尺寸、EXIF、动图、HDR 和动态照片识别；罕见的 PNG/WebP 尾部 EXIF 保留文件解析回退。视频元数据与详情复用同一次 ffprobe。未改变文件继续只比较 stat。旧编码缓存清理在后台运行，不延迟同步打开图库。

分页 DTO、日期分组和媒体标志在同一 DbActor 调用/读取事务中返回，分组可随窄索引缓存。仅收藏变化复用未按收藏筛选的排序索引，结构已变化的索引不能被错误提升 revision。后台缩略图核对使用独立分页查询，避免覆盖前台排序索引。

同步上传仅使用已生成的本地缓存；缺少缓存为 deferred，不解码原图，不创建 issued/staging，不记为上传失败。元数据下行最多 100 条事务写入、一次重计数；相同重放无写入。上行按 20 条元数据/5 张照片合作让出执行，保持原 lease 顺序；300 ms 合并的变更通知使界面按批次增量更新。
