# 隐藏子目录与回收站监听（2026-10-23）

Linux 与 Android 共用相同的来源目录可见性规则。遍历已选择的来源时，遇到任一名称以 `.` 开头的子目录，立即跳过整棵子树，不再枚举或读取其中媒体。规则相对于来源根目录判断，来源上级路径中的 `.local` 等目录不会把整个来源误判为隐藏内容；普通目录里的 `.photo.png` 文件也不受“隐藏文件夹”规则影响。

文件变更在监听回调入口采用同一规则：隐藏目录及其内部文件的创建、修改、删除不会设置扫描脏标记，不触发后台扫描，也不写入 `filesystem_scan` 日志。重命名事件只要有可见的一端就仍会触发核对，支持照片移入或移出隐藏目录。

入库入口还会拒绝来自隐藏子目录的媒体。打开旧图库时，原先已收录的相关活动记录会在事务中退出可见图库并更新总数；保留记录身份、收藏信息和原文件，不产生云端删除任务。回收站中的记录保留其回收状态；外部恢复后会再次应用来源目录规则。

## 两端回收站

| 平台 | 实际实现与监听例外 |
| --- | --- |
| Linux | 继续使用现有 GIO / freedesktop 回收站。监听 `$XDG_DATA_HOME/Trash`、`~/.local/share/Trash`，以及来源挂载点上的 `.Trash-UID`、`.Trash/UID`。这些实际路径接收明确的例外，普通同名隐藏目录不会因此获准入库。 |
| Android | 使用应用图库根目录内部的 `Trash/files`、`Trash/info`。该位置原先会被“忽略图库自身写入”的规则一并排除，现在明确允许其变更通过。安装监听前准备目录，确保第一次移入回收站也能被观察。 |

回收站位置只用于回收状态核对，不作为普通照片来源扫描；手动扫描与后台扫描都排除这些实际回收站路径。Linux 回收站尚未创建时，先监听已有上级目录；创建后重新注册递归监听，继续接收恢复和外部清空事件。
