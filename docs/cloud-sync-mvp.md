# 云同步 MVP（二期）

日期：2026-10-22。状态：MVP 已完成原桌面端到端验收；本轮补齐通用元数据事件与持久化请求确认，验证范围见下文及[策略对齐记录](cloud-sync-alignment.md)。

本期按公开的 `sync-client` SDK 接入云同步。所有协议操作（登录、快照/增量、记录读取、资源下载、租约、上传、操作回执）都经 SDK 完成；应用不自行实现 HTTP、CloudKit 或 JSON 协议。SDK 以固定提交引入：

```text
https://github.com/Luyao-1024/syncserver.git
rev = 9097be58dbec0cc441ebb46068dc81f72d537368
```

## 本期范围

- 账号登录/退出，普通用户图库能力；管理员账号明确拒绝。
- 首次快照与增量下行；原图与缩略图落盘后可正常浏览。
- 收藏双向同步。
- 当前图库中显式选择的照片上行（原图 + JPEG 缩略图）。
- 启动后同步一次，设置页可手动“立即同步”；没有后台轮询或定时同步。

不包含：云端删除/回收站操作、内容替换、完整冲突处理界面、多账号切换、后台同步、仅缩略图占位。

## 数据与文件

| 内容 | 位置/规则 |
|---|---|
| 令牌 | `<数据目录>/cloud/<account_id>/session.token`，目录 `0700`，文件 `0600`，临时文件 + rename 写入 |
| 数据库 | schema v5 保存账号、令牌文件路径、同步 token、通用 dirty/版本/编辑事件，以及已发送元数据请求的标量快照；不保存密码、令牌内容、能力 URL 或 receipt |
| 下载 | `<数据目录>/cloud/<account_id>/media/<photo_id>/<generation>/original.<ext>` 与 `thumbnail.<jpg\|png>` |
| 发布 | 先写同目录 `.part`，SDK 校验大小与 SHA-256 后 rename 并 fsync 目录 |
| 上传路径 | `Uploads/<year>/<stem>-<media8>-<generation8><ext>`，由 SDK 的安全相对路径检查 |

退出登录会删除令牌文件，但保留账号记录、绑定和已下载文件，图库仍可离线浏览（只读）。密码只在登录调用期间留在内存中，不进入数据库、日志或错误文本；界面与数据库只出现稳定错误码。

## 同步语义

1. 下行先缓存全部分页，只有 `more_coming == false` 后才从完整记录重建图；`CPLMaster`/`CPLAsset` 分页拆分不会产生半张照片。
2. 只有本轮全部下载原子落定后才推进 sync token；失败时不推进，下次幂等重放。
3. 远端删除、隐藏或回收站状态：本地文件与绑定保留，媒体标记为 `missing`，不物理删除；恢复可见后重新激活。
4. 内容 generation 变化：标记 `content_stale`，保留旧内容，不自动替换。
5. 收藏作为通用元数据编辑：在本地事务内递增本地/元数据版本，保存真实编辑时间、来源和事件 ID，已同步照片置 `dirty=2`。下行按编辑时间、来源、事件 ID 裁决同类别并发修改；双方均缺失事件时保留本地待办，已确认的旧云事件不能覆盖后来的本地编辑。
6. 新增上行只针对显式选择的照片，已绑定照片的元数据编辑自动成为待办。上行使用单一租约，按删除 → 修改 → 新增阶段推进；失锁立即停止，不回退已提交操作。当前不产生云端删除或内容替换操作。
7. 上传重试复用固定的 operation ID；在读取原图、生成缩略图前先查 `operation_status`，Pending 不重发。下行完整记录图中的照片若匹配持久化上传意图的 photo/master/generation，先恢复原媒体 ID 的绑定，再判定下载，避免提交回执丢失后重复导入。
8. 元数据发送前持久化通用请求 UUID、原始条件版本、元数据值、编辑事件和捕获的本地/元数据版本；重试复用整份请求。只在返回的照片身份、版本、值和事件吻合后确认所捕获的版本，后来的编辑继续保留 `dirty=2`。没有收藏等字段专用的操作键。
9. 新照片发布后，若仍有本地元数据事件未确认，在后续修改租约中发送该事件，保留上传前的实际编辑时间。
10. 缩略图长边依次尝试 2048/1600/1200/800，直到 JPEG 不超过 2 MiB。
11. 完整记录图验证通过后，在单个事务中批量刷新绑定的远端路径，支持改名、路径交换和旧路径复用；已删除照片仍保留绑定、只读保护和文件，其绑定路径使用仅本地保留值释放原路径。

## 只读与来源

- 云端绑定的照片在应用内只读：编辑、重命名、移入回收站、移动相册被禁用；收藏、复制、导出可用。
- 云媒体目录作为 `managed` 来源管理，不出现在设置的来源列表，不能被移除，也不会被普通目录扫描或自动发现重复导入。
- 缩略图本地生成失败时，网格回退到同步下载的云端缩略图。

## 操作与限制

- 设置 → 云同步：服务器地址、用户名、密码、登录/退出、立即同步、上次同步与待办计数。
- 服务器地址必须是完整 URL（例如 `http://127.0.0.1:8790`）；SDK 不接受 `localhost`。
- 一个数据目录只允许一个账号；更换账号需要新的数据目录。
- 无云端删除/回收站 UI；临时同步失败先看错误码文案，网络恢复后再次同步即可。
- 开发/验收阶段使用隔离 SyncServer 与独立 `--data-root`；真实图库验收仍按 `AGENTS.md` 启动。

## 验证

`tools/cloud_e2e` 启动相邻 `../syncserver` 的真实二进制，使用独立服务端数据目录和随机账号，把真实图库数据库通过 SQLite backup 快照成两个客户端数据根，再以虚拟 X11 桌面运行发布包。覆盖登录/退出、首次下行、缩略图与原图落盘、云标识、只读保护、收藏双向、相册内显式批量上传、单张上传、断网启动、离线排队与重连恢复。证据目录保留 `report.json`、每个阶段的 journey trace 和截图；不会把真实照片截图提交到仓库。

结果与服务端核对：3 张照片（2 张上传 + 1 张离线重连上传）、2 个收藏双向生效、客户端下载文件与服务端 SHA-256/大小一致、令牌 `0600`、账号目录 `0700`。详见[云同步端到端验收](verification/cloud-sync-e2e.md)。
