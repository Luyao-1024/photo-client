# 云同步 MVP（二期）

日期：2026-10-22。状态：MVP 已完成原桌面端到端验收；本轮补齐通用元数据事件与持久化请求确认，验证范围见下文及[策略对齐记录](cloud-sync-alignment.md)。

本期按公开的 `sync-client` SDK 接入云同步。所有协议操作（登录、快照/增量、记录读取、资源下载、租约、上传、操作回执）都经 SDK 完成；应用不自行实现 HTTP、CloudKit 或 JSON 协议。SDK 以固定提交引入：

```text
https://github.com/Luyao-1024/syncserver.git
rev = 9097be58dbec0cc441ebb46068dc81f72d537368
```

## 本期范围

- 账号登录/退出，普通用户图库能力；管理员账号明确拒绝。
- 首次快照与增量下行；原图与缩略图落盘后可正常浏览。
- 收藏双向同步。
- 当前图库中显式选择的照片上行（原图 + JPEG 缩略图）。
- 已绑定照片的编辑、改名、移动相册、回收站/恢复和永久删除全部可上行。
- 登录与同步分离：登录只建立会话并立即返回结果，不触发任何下行。
- 同步由设置页“立即同步”、自动同步开关和本地变更触发。“自动同步”（默认关闭）开启后立即同步一次；本地照片或收藏变更停止 10 秒后自动同步一次；应用启动时同步一次。没有空闲轮询或定时同步。

不包含：完整冲突处理界面、内容冲突受保护副本的展示、仅缩略图占位。

## 数据与文件

| 内容 | 位置/规则 |
|---|---|
| 令牌 | `<数据目录>/cloud/<account_id>/session.token`，目录 `0700`，文件 `0600`，临时文件 + rename 写入 |
| 数据库 | schema v7 保存账号、令牌文件路径、同步 token、通用 dirty/版本/编辑事件、已发送元数据请求的标量快照，以及内容与删除义务的捕获版本、摘要、条件和事件；不保存密码、令牌内容、能力 URL 或 receipt |
| 下载 | `<数据目录>/cloud/<account_id>/media/<photo_id>/<generation>/original.<ext>` 与 `thumbnail.<jpg\|png>`；`photo_id` 不是 UUID 时退化为安全目录名加摘要 |
| 发布 | 先写同目录 `.part`，SDK 校验大小与 SHA-256 后 rename 并 fsync 目录 |
| 上传路径 | `<相册路径>/<stem>-<media8>-<generation8><ext>`，相册路径是本地相册相对其来源根的路径；无法安全表达时退回 `Uploads/<year>/…`；由 SDK 的安全相对路径检查 |
| 下载相册 | `<数据目录>/cloud/<account_id>/<云端相对路径的目录>`，与上传时的相册同名；没有目录的路径落在 `Cloud` |

退出登录会删除令牌文件，但保留账号记录、绑定和已下载文件，图库仍可离线浏览；未登录期间不会产生同步。密码只在登录调用期间留在内存中，不进入数据库、日志或错误文本；界面与数据库只出现稳定错误码。

## 相册语义

1. 上行时照片的云端相对路径携带它所在的相册：本地相册路径相对来源根（例如 `Camera/2026-09`）成为云端路径的前缀，文件名保留去重后缀以保证同 zone 内唯一。
2. 下行时照片落在与云端相对路径同名的相册里，而不是一个统一的 Cloud 相册；相册是虚拟目录，字节仍在按 generation 分目录的媒体文件夹里。
3. 往返因此是对称的：从相册 A 上传的照片，在另一端仍回到相册 A。
4. 相册路径的每一段都必须是安全路径段：空段、`.`、`..`、反斜线、NUL 以及服务端保留目录 `.syncserver`、`.photoviewer-sync`、`.sync-staging` 都不会出现在云端路径里。

## 登录语义

1. 登录只做三件事：解析服务器地址、建立会话并把令牌落盘、把账号写进本地库。口令只在这次调用期间留在内存。
2. 登录不触发任何下行、上行或租约。会话建立后立即返回结果，界面当场显示账号或稳定错误码，不存在“登录中一直转圈”的中间态。
3. 下行只由显式同步动作或已开启的自动同步触发：设置页的“立即同步”；自动同步开启后的应用启动；本地照片或收藏变更停止 10 秒后；以及切换账号、变更上传范围后的立即触发。自动同步默认关闭，空闲时不会周期同步。
4. 同步进行中界面显示“同步中…”并刷新已绑定计数；同步失败只影响同步状态，不撤销已经建立的登录。

## 同步语义

1. 下行先缓存全部分页，只有 `more_coming == false` 后才从完整记录重建图；`CPLMaster`/`CPLAsset` 分页拆分不会产生半张照片。
2. 只有本轮全部下载原子落定后才推进 sync token；失败时不推进，下次幂等重放。
3. 远端删除、隐藏或回收站状态：本地文件与绑定保留，普通图库按状态隐藏，不物理删除；本地待办或本地回收站状态不被下行覆盖，恢复可见后重新激活。本地移入回收站/恢复上传 `isTrashed` 元数据，永久删除上传云端删除。
4. 内容 generation 变化：标记 `content_stale`，保留旧内容，不自动替换本地待办。
5. 收藏作为通用元数据编辑：在本地事务内递增本地/元数据版本，保存真实编辑时间、来源和事件 ID，已同步照片置 `dirty=2`。下行按编辑时间、来源、事件 ID 裁决同类别并发修改；双方均缺失事件时保留本地待办，已确认的旧云事件不能覆盖后来的本地编辑。
6. 新增上行只针对显式选择的照片，已绑定照片的编辑、改名、移动、收藏、回收站/恢复和永久删除自动成为待办。上行使用单一租约，按删除 → 修改（内容先于元数据）→ 新增推进；失锁立即停止，不回退已提交操作。
7. 上传重试复用固定的 operation ID；在读取原图、生成缩略图前先查 `operation_status`，Pending 不重发。内容替换、元数据修改和删除分别冻结自己的请求；下行完整记录图中的照片若匹配持久化上传意图的 photo/master/generation，先恢复原媒体 ID 的绑定，再判定下载，避免提交回执丢失后重复导入。
8. 元数据发送前持久化通用请求 UUID、原始条件版本、元数据值、编辑事件和捕获的本地/元数据版本；重试复用整份请求。只在返回的照片身份、版本、值和事件吻合后确认所捕获的版本，后来的编辑继续保留 `dirty=2`。没有收藏等字段专用的操作键。
9. 内容替换在发送前冻结内容 operation：捕获内容/媒体版本、generation、原图与缩略图摘要；发送前校验当前文件仍能重建同一摘要，不一致则放弃该 operation 并重新捕获。确认时只 ack 捕获的内容版本，上传期间再次编辑继续保留待办。
10. 永久删除先在本地写墓碑（`dirty=4`、删除事件与版本），绑定和媒体行保留到云端 Delete 确认；Delete 阶段原子删除照片的两条记录，远端已不存在同样视为完成，随后才移除绑定，媒体行在最后一个账号绑定移除后删除。
11. 新照片发布后，若仍有本地元数据事件未确认，在后续修改租约中发送该事件，保留上传前的实际编辑时间。
12. 缩略图长边依次尝试 2048/1600/1200/800，直到 JPEG 不超过 2 MiB。
13. 完整记录图验证通过后，在单个事务中批量刷新绑定的远端路径，支持改名、路径交换和旧路径复用；远端已删除或回收站照片保留绑定与文件，其绑定路径使用仅本地保留值释放原路径。绑定照片改名/移动相册会更新云端路径，仅收藏或回收站变化不重写路径。

## 清理语义

设置 → 存储与日志 → “缓存与云端数据” 的“清理”是一次彻底的复位，数据库与磁盘同时处理：

1. 数据库先行：删除云端账号、会话状态、同步记录、绑定、上传队列与已发元数据请求；删除来自 `managed` 云端来源的媒体行及其缩略图、相册成员、文件操作、编辑工程与图库成员关系；重置本机照片的待办标记，使它们回到“从未同步”的干净状态。
2. 磁盘随后：删除 `<数据目录>/cloud` 整个目录（下载的照片、原图、缩略图与会话令牌）和缩略图缓存目录，并清空 `thumbnails` 表的行。
3. 数据库行与磁盘文件必须成对清除：只删文件而留下“已就绪”的行，会让候选查询以为缩略图还在，照片将不再重新生成。缩略图清理由加载器在发布锁内完成，避免清理途中有任务把缩略图写回。
4. 清理前有确认对话框，写明会删除缩略图缓存、已下载的云端照片、云端会话与同步记录，并显示当前占用的云端数据体积。
5. 本机照片永远不会被删除：它们的字节、来源与相册保持原样。
6. 清理后应用回到未登录状态；再次登录并同步会重新下载云端照片。

## 来源与可编辑性

- 云端绑定的照片没有只读限制：编辑、旋转、重命名、移动相册、收藏、移入回收站/恢复和永久删除都可执行，并分别生成内容、路径、元数据或删除的同步义务；云端不可达时先保留本地待办，恢复后继续上行。
- 云媒体目录作为 `managed` 来源管理，不出现在设置的来源列表，不能被移除，也不会被普通目录扫描或自动发现重复导入。
- 缩略图本地生成失败时，网格回退到同步下载的云端缩略图。

## 操作与限制

- 设置 → 云同步：服务器地址、用户名、密码、登录/退出、自动同步开关、立即同步、上次同步与待办计数。
- 服务器地址必须是完整 URL（例如 `http://127.0.0.1:8790`）；SDK 不接受 `localhost`。
- 同时只有一个活动账号；可保存多个账号并切换，切换后按自动同步开关决定是否立即同步。
- 无单独“云端删除/回收站”界面；回收站和永久删除使用图库现有操作，永久删除在云端 Delete 确认前不会丢失本地墓碑。
- 冲突处理仍以稳定错误码和后续重试为主，没有完整的冲突合并界面；内容冲突的受保护副本展示未包含在本期。
- 开发/验收阶段使用隔离 SyncServer 与独立 `--data-root`；真实图库验收仍按 `AGENTS.md` 启动。

## 验证

`tools/cloud_e2e` 启动相邻 `../syncserver` 的真实二进制，使用独立服务端数据目录和随机账号，把真实图库数据库通过 SQLite backup 快照成两个客户端数据根，再以虚拟 X11 桌面运行发布包。覆盖登录/退出、首次下行、缩略图与原图落盘、云标识、可编辑性、收藏双向、相册内显式批量上传、单张上传、断网启动、离线排队与重连恢复。`crates/photo-core/tests/cloud_sync_unrestricted.rs` 另用真实 SyncServer 验证改名路径、回收站/恢复、内容替换和永久删除的上行与回读。证据目录保留 `report.json`、每个阶段的 journey trace 和截图；不会把真实照片截图提交到仓库。

结果与服务端核对：3 张照片（2 张上传 + 1 张离线重连上传）、2 个收藏双向生效、客户端下载文件与服务端 SHA-256/大小一致、令牌 `0600`、账号目录 `0700`。详见[云同步端到端验收](verification/cloud-sync-e2e.md)。
