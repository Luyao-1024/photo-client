## 环境与数据

- 服务端：相邻 `../syncserver` 的真实发布二进制，`127.0.0.1` 独立 HTTP 端口，独立数据目录、签名密钥和随机验收账号；每个证据目录重新创建服务端状态。
- 客户端：发布包 `app/build/linux/x64/release/bundle/photo_client`，通过真实 FFI、SQLite、文件系统和窗口运行。
- 数据：把用户真实图库数据库经 SQLite backup 快照到两个客户端数据根。照片和元数据来自真实图库；快照隔离只用于避免验收上传/收藏改写正在使用的图库。验收选择图库中真实的单照片相册，以证明上传不会越过显式选择。
- 显示与输入：`Xvfb` 虚拟 X11 桌面（`:90`–`:99`），`xdotool`/XTest 注入真实指针、键盘与右键事件。密码只通过子进程环境变量 `PHOTO_CLOUD_PASSWORD` 传递。

## 阶段与断言

| 阶段 | 覆盖 |
|---|---|
| `cloud-upload` | 空数据库登录；设置页账号/服务器显示；只在显式选中的单照片相册内批量上传；右键单张上传；云朵徽标；查看器原图解码；编辑/回收站/旋转/重命名禁用且 Delete 无效；收藏上行；退出登录后令牌删除但照片、绑定、云朵徽标保留 |
| `cloud-download` | `localhost` 地址被拒绝；错误密码返回 `AuthFailed`；正确登录后首次下行；缩略图与原图文件落盘并可解码；网格云朵徽标；查看器原图尺寸与记录一致；远端收藏自动应用；本机收藏上行 |
| `cloud-offline` | 服务端停止后启动上报 `Network`、保留会话与本地云照片；离线查看原图；离线上传进入持久队列；离线退出登录保留队列；离线重新登录失败 |
| `cloud-reconnect` | 服务端恢复后重新登录；离线队列上传成功；队列清零、错误码清除；本地相册照片获得云朵徽标；下载文件数与远端媒体一致 |
| `cloud-reconcile` | 另一数据根重新登录；新上传照片下行并带云朵徽标；另一端的收藏应用到本地；两端绑定数一致 |

编排器在全部应用进程结束后通过真实 HTTP 会话核对服务端：`/v1/console/photos`、`/v1/console/photos/{id}`、`/v1/console/summary` 与 `/v1/storage`。逐张比较客户端下载的原图/缩略图与服务端 `fileChecksum`、大小，核对上传/下载分布（2/1 与 1/2）、收藏、配额占用、令牌权限位。

## 运行

```bash
PHOTO_FLUTTER_ROOT=/path/to/flutter ./tools/cloud_e2e \
  --evidence-dir /path/to/fresh-evidence
```

`--skip-build` 复用已构建的发布包和服务端二进制；`--library` 可指定真实图库数据库。证据目录必须为空，`report.json` 记录每条命令、阶段记录、截图清单和服务端核对结果。自动验收不会提交真实照片截图，证据保留在本地。
