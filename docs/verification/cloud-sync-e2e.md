## 阶段与断言

| 阶段 | 覆盖 |
|---|---|
| `cloud-upload` | 空数据库登录；设置页账号/服务器显示；只在显式选中的单照片相册内批量上传；右键单张上传；云朵徽标；查看器原图解码；编辑/回收站/旋转/重命名禁用且 Delete 无效；收藏上行；退出登录后令牌删除但照片、绑定、云朵徽标保留 |
| `cloud-download` | `localhost` 地址被拒绝；错误密码返回 `AuthFailed`；正确登录后首次下行；缩略图与原图文件落盘并可解码；网格云朵徽标；查看器原图尺寸与记录一致；远端收藏自动应用；本机收藏上行 |
| `cloud-offline` | 服务端停止后启动上报 `Network`、保留会话与本地云照片；离线查看原图；离线上传进入持久队列；离线退出登录保留队列；离线重新登录失败 |
| `cloud-reconnect` | 服务端恢复后重新登录；离线队列上传成功；队列清零、错误码清除；本地相册照片获得云朵徽标；下载文件数与远端媒体一致 |
| `cloud-reconcile` | 另一数据根重新登录；新上传照片下行并带云朵徽标；另一端的收藏应用到本地；两端绑定数一致 |

## 云同步恢复定向回归

`cloud_sync_recovery` 只验证收藏与上传恢复、远端路径复用，不启动桌面或读取真实图库。每个用例使用独立真实 SyncServer、随机测试账号、临时图库和生成的 JPEG。用例默认忽略，需先准备已构建的相邻 `../syncserver/target/release/syncserver`，或用 `PHOTO_SYNC_SERVER_BIN` 指向服务端二进制，再显式执行：

```bash
cargo test --locked -p photo-core --test cloud_sync_recovery -- --ignored
```

覆盖重复收藏/取消收藏、相同观察版本的操作重试及元数据保留、上传提交但本地未记账时的恢复、原图缺失后的恢复，以及远端改名后在旧路径新增照片。断点状态直接写入隔离数据库，检查媒体 ID、文件、待办与服务端状态；不依赖随机断线时序。

路径交换、删除后复用和事务失败回滚另由 `local_library::cloud_store::tests` 中的 `binding_paths_swap_atomically_without_changing_media_identity`、`orphan_binding_releases_its_path_and_can_later_return`、`binding_path_conflict_rolls_back_the_entire_remap` 定向单测覆盖。

## 通用元数据同步回归（schema v5）

2026-10-22 将收藏专用修补替换为重构前的通用元数据版本/事件/请求确认机制。`cloud_sync_recovery` 的定向范围现为 9 项：

- 连续收藏、取消、再收藏：逐次核对 `dirty=2→0`、云端值，以及返回的本地编辑时间/来源/事件 ID。
- 同一已冻结请求重复发送：请求 ID、条件版本、载荷与编辑事件均不变化；元数据其他值保留。
- 服务端已提交、本地未确认：关闭 actor、重开真实 SQLite 图库，读取回执后确认原捕获版本。
- 请求尚未发送时重启：重放原持久请求，并保留其后发生的本地编辑供下一轮上传。
- 上传期间修改后改回原值，即使三次时间相同，旧回调也不能确认第三次编辑。
- 新照片上传前已有元数据编辑：保留实际离线编辑时间，不接受服务端提交时间替代。
- 新增照片提交后恢复，包含原图仍在/已缺失两个分支：不重复导入，媒体 ID 保持一致。
- 远端改名后在旧路径新增：更新路径绑定后正常接收，不阻塞 token。

部分用例包含多项断言，以上按行为列举；实际测试函数数量为 9。断点由隔离数据库状态注入，包含真实关闭/重开图库，不声称杀死了客户端进程。服务端使用相邻已有发布二进制。未重跑完整桌面旅程。

新增跨重启身份检查：持久命名空间或数据库代际不匹配时，真实服务端用例验证在重放前返回 `CloudScopeChanged`，本地 dirty 与已固定代际不被覆盖，服务端照片不被修改。
